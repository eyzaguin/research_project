SQL analysis

Explore which musical characteristics are associated with Spotify song popularity.

Assignment brief

What makes a song popular?

Use the Spotify Tracks Dataset | Audio Features to investigate your research question: What musical characteristics are associated with higher song popularity on Spotify? Query popularity alongside danceability, energy, tempo, duration, and genre. Treat your results as associations, not evidence that an audio feature causes popularity.

Course · TECH*3745*01
Professor · Xiwang Guo

Part 01 · Query the data

Write at least eight queries.

Use the cleaned Spotify tracks data from your earlier assignments. The examples use the dataset's field names; adjust table or column names only if your prepared file differs. Run each query and include its SQL and result in your submission.

Project data · Spotify Tracks Dataset | Audio Features

tracks (track_name, artists, track_genre, popularity, danceability, energy, tempo, duration_ms, ...)

genres (track_genre) · a distinct genre lookup made from the tracks' track_genre values for the JOIN query

  1. Basic selection

    Inspect track popularity alongside the audio features in your research question.

    SELECT track_name, artists, track_genre,
       popularity, danceability, energy, tempo, duration_ms
FROM tracks;

  2. Filtering

    Filter to tracks with a higher popularity score and relevant feature data.

    SELECT track_name, popularity, danceability
FROM tracks
WHERE popularity >= 70;

  3. Multiple conditions

    Find tracks with both higher danceability and higher energy, then compare their popularity.

    SELECT track_name, popularity, danceability, energy
FROM tracks
WHERE danceability >= 0.7 AND energy >= 0.7;

  4. Sorting

    List the most popular tracks first.

    SELECT track_name, artists, track_genre, popularity
FROM tracks
ORDER BY popularity DESC
LIMIT 20;

  5. Aggregation

    Summarize the dataset's size and overall popularity and audio-feature averages.

    SELECT COUNT(*) AS track_count,
       AVG(popularity) AS avg_popularity,
       AVG(danceability) AS avg_danceability,
       AVG(energy) AS avg_energy
FROM tracks;

  6. Group comparison

    Compare average popularity and track counts across genres.

    SELECT track_genre, COUNT(*) AS track_count,
       AVG(popularity) AS avg_popularity
FROM tracks
GROUP BY track_genre
ORDER BY avg_popularity DESC;

  7. Filtering groups

    Compare genres only when they have enough tracks for a more meaningful average.

    SELECT track_genre, COUNT(*) AS track_count,
       AVG(popularity) AS avg_popularity
FROM tracks
GROUP BY track_genre
HAVING COUNT(*) >= 100
ORDER BY avg_popularity DESC;

  8. Joining tables

    Join each track to the genre lookup table and compare popularity by genre.

    SELECT genres.track_genre, COUNT(*) AS track_count,
       AVG(tracks.popularity) AS avg_popularity
FROM tracks
JOIN genres ON tracks.track_genre = genres.track_genre
GROUP BY genres.track_genre
ORDER BY avg_popularity DESC;

Before comparing genre averages, check how many tracks each genre contains and whether the dataset is balanced. Popularity can also reflect artist recognition, marketing, playlist placement, and other factors not represented by audio features.

Part 02 · SQL to visualization

Visualize two query results.

Use the basic selection result to plot popularity against danceability as a scatterplot, looking for an association while noting overlap and outliers. Use the genre GROUP BY result to compare average popularity across genres with a sorted bar chart. Label both charts, identify the query behind each, and discuss patterns without implying causation.

Part 03 · Research connection

Connect queries to your question.

Explain how the queries test the project's sub-questions about danceability, energy, and genre differences in popularity. Summarize what the visualizations suggest, whether the results support your preliminary hypotheses, and how genre imbalance or missing factors such as marketing and artist recognition limit your conclusions.
