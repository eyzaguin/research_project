Dataset & purpose

Prepare the tracks for analysis.

This project asks which musical characteristics are associated with higher Spotify popularity. Preparation uses the same Spotify Tracks Dataset | Audio Features used in the proposal and exploratory analysis.

The original CSV has 114,000 records, 20 columns, and 114 genre labels. I audited the full source file, applied explicit type and format conversions, removed exact duplicate rows, preserved multi-genre track assignments, and flagged questionable records for review rather than silently deleting them.

Preparation audit · original CSV

Investigate before changing the data.

These counts come from parsing the complete Kaggle CSV. Each decision is recorded so the cleaned dataset remains traceable and suitable for the research question.

  1. 01

    Missing values

    Audit: Three blank metadata cells were found: one each in artists, album_name, and track_name. No numeric research-feature values were blank.

    Action: Keep the descriptive cells blank and flag the affected row. Do not invent track names or artists. The row still has research fields and remains in the prepared file; exclude it only from an analysis that requires the missing label.

  2. 02

    Duplicate records

    Audit: 450 rows were exact full-row duplicates. While 24,259 rows repeat a track_id, 16,299 track IDs are assigned to multiple genre labels.

    Action: Remove only the 450 exact duplicate rows, leaving 113,550 records. Do not deduplicate by track_id alone: that would erase meaningful genre assignments. The prepared data preserves distinct track–genre records.

  3. 03

    Incorrect data types

    Audit: CSV fields need explicit types when imported; all 14 numeric columns parsed without errors, and every explicit value parsed as a boolean.

    Action: Read identifiers, names, and genre labels as text; cast numeric measures and category codes to numeric values; convert explicit to true/false. Keep IDs as text so they are never treated as measurements.

  4. 04

    Inconsistent formats

    Audit: Leading or trailing whitespace occurred in eight artists cells and one track_name cell. No genre spelling/case variants were found.

    Action: Trim surrounding whitespace from text fields and normalize genre labels to lowercase. Preserve internal punctuation, spelling, and genre distinctions such as pop-film.

  5. 05

    Invalid values

    Audit: Popularity scores fall within 0–100 and bounded audio features fall within their expected 0–1 ranges. One record has zero duration; 157 records report tempo as 0.

    Action: Retain valid popularity zeros; they are scores, not missing values. Flag zero duration and zero tempo as data-quality issues. Keep affected records for analyses of other valid fields, and exclude them only from the relevant duration- or tempo-specific calculation.

  6. 06

    Outliers

    Audit: After exact duplicates were removed, Tukey’s 1.5 × IQR rule flagged 6,540 records on at least one of popularity, danceability, energy, tempo, duration, or valence. Duration contributed the most flags; 79 tracks are over 20 minutes, and 16 are under 30 seconds.

    Action: Add field-specific outlier flags but do not automatically delete valid extremes. Verify implausible records against the source and use medians, distributions, and sensitivity checks when outliers could affect summaries.

  7. 07

    Inconsistent categorical values

    Audit: The source contains 114 distinct genre labels, with no whitespace or capitalization variants. explicit contains only valid true/false values.

    Action: Standardize text formatting without merging genres. Preserve all 114 category labels and the distinction between tracks that carry multiple genre assignments.

  8. 08

    Data transformations

    Action: Retain duration_ms and add duration_min for readable summaries and charts. Add a prep_flags field for missing metadata, repeated track–genre records, zero tempo, zero duration, and IQR outliers. No popularity scores or valid feature measurements are rescaled or imputed.

    Result: The prepared file contains 113,550 rows and 22 columns. Genre sample sizes range from 904 to 1,000 after exact duplicates are removed.

  9. 09

    Research connection · Data Preparation / Methodology

    Paper-ready method: “The Spotify tracks CSV was imported with explicit text, numeric, and boolean types. Text whitespace was trimmed and genre labels standardized. The preparation removed 450 exact duplicate rows while retaining distinct track–genre assignments. Three missing descriptive metadata cells were left blank and flagged rather than imputed. Popularity zeros and valid audio-feature values were retained. Zero-duration and zero-tempo records and Tukey IQR outliers were flagged for review rather than automatically removed. Track duration in minutes and a preparation-flags field were added while preserving the original duration in milliseconds. These decisions maintain the sample’s audio and popularity evidence while making exclusions transparent and reproducible.”

    Use this methodology in the paper, and explain any later analysis-specific exclusions separately.

Exploratory prediction · prepared dataset

Popularity model comparison.

The proposal treats Spotify popularity as a numeric outcome, so this is a regression task. The prepared 113,550-row dataset was split 80/20 by track_id so rows for the same track stay in one partition. All scores below are measured on the held-out test set.

Accuracy is not applicable: accuracy is for classification labels. For a numeric popularity score, compare mean absolute error (MAE), root mean squared error (RMSE), and R². Lower MAE/RMSE and higher R² indicate better test-set predictions.

Result: The genre-mean baseline performs best (RMSE 19.2672; R² 0.2512). The audio-feature decision tree performs slightly better than linear regression, but its R² is only 0.0435. In this comparison, genre averages provide more predictive information than the tested audio features alone.

Interpret carefully: These are predictive associations, not evidence that genre or any audio feature causes popularity. The genre baseline uses track_genre; the other two fitted models intentionally use audio features only. The split keeps the same track ID out of both training and test sets.
